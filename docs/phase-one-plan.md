# Phase One: simulation core and balance laboratory

## Objective

Build the smallest deterministic game simulation that can run automatic lives and answer progression questions before substantial content or interface work begins.

## Included game logic

- Acts and stages with guaranteed actions and chance-based encounter buckets.
- Automatic action execution and stage transfer.
- Vitality decay and ordinary return to the anchor.
- Regular discipline experience that resets on anchor return.
- Dimensional discipline experience that persists through anchor return.
- Discipline levels, action speed, XP requirements, and configurable softcaps.
- Encounter rewards, fights, recovery, journal discovery, and automatic stage progress.
- Rarity-based action completion thresholds that unlock journal toggles.
- Dimensional shards generated by the background clone.
- Soulbound summoning with progression-controlled rarity pools.
- Persistent versus current-life state boundaries.

## Balance laboratory

The simulator must use the same rules and content definitions as the game runtime. It should run deterministic scenarios and seeded batches of lives, then report:

- time to each stage and act;
- regular and dimensional discipline levels;
- offline and active efficiency;
- vitality remaining and return frequency;
- encounter frequency and journal completion;
- shards generated and time to soulbound summons;
- effects of equipment, softcaps, and multipliers;
- bottleneck actions, pending story dependencies, and action-cost warnings.

The first interface can be a command-line runner that emits JSON or CSV plus simple charts. A browser dashboard can be added after the model is stable.

## Phase One exclusions

- final dimensional-shift rules;
- warrior-dimension multiplayer;
- production UI and visual presentation;
- large-scale content authoring.

Full inventory management, temporary equipment, and custom clone routes are not approved mechanics or planned later phases. Equipment means the summoned soulbound collection and loadout; the clone is a passive dimensional-shard accumulator. Do not add these superseded systems as implementation extension points.

## Completion criteria

Phase One is complete when the simulator can reproduce the same result as the headless game simulation for a seeded run, compare active and inactive progression, and show when new acts, encounters, summon pools, and clone features should unlock without relying on intuition alone.

## Current implementation

- `src/dimensional_sim/core.py` contains the deterministic state model and automatic life runner.
- `src/dimensional_sim/balance.py` runs seeded batches, active/offline comparisons, equipment variants, and action-graph export.
- `src/dimensional_sim/cli.py` exposes the simulator from the command line.
- `tests/test_core.py` verifies deterministic replay, XP reset boundaries, offline progress, journal toggles, sequential story progression, summon validation, and save/load continuation.
- `docs/technical/simulator.md` documents the developer workflow.


## Review status (2026-09-20)

Simulation correctness fixes and expanded reporting pass 40 tests. An isolated

progress; see [the implementation review](implementation-review-2026-09-20.md)
for measured pacing issues and outstanding criteria.

Content definitions live in src/dimensional_sim/content.py; safe RNG migration
lives in src/dimensional_sim/persistence.py. Regression and balance coverage is
in tests/test_regressions.py and tests/test_balance.py.


## Confirmed action prerequisites

Story stages require only completion of the preceding story action. Bucket
actions require completion of their story action and either a rolled place in
the current life or an enabled journal unlock. There are no discipline-level
access gates. tests/test_progression.py verifies these rules and save migration.
The earlier review statistics predate this correction and are historical.
